Overview

agibot-g2-humanoid-packoff-cell is a simulated work cell for a humanoid robot at the end of a packing line. The products are flexible, sealed bags, for example bags of salad leaves, bags of crisps and other pillow packs. The robot picks the bags from a table and puts them into cartons on a conveyor. It puts rejected bags into totes in a sort rack.

Pack-off is a manual task in many fresh-produce and snack factories. The cell lets a team develop the robot tasks, collect demonstration data and train policies before a test on a real line.

The reference robot is the AgiBot G2. It has a wheeled base, a waist, two 7-DoF arms with grippers and a head RGB-D camera. The cell runs on AgiBot Genie Sim 3.2 with NVIDIA Isaac Sim 6.0.1. It runs headless in Docker, so it runs on a workstation or on a cloud GPU server.

The bags in the simulation are rigid placeholders at this stage. Deformable bags are a next step. All tests used simulation only. No test on a real robot is complete.

What the cell supports

  • Develop pick, place and sort tasks for a wheeled dual-arm humanoid.
  • Teleoperate the arms from a keyboard over SSH, or with a SpaceMouse.
  • Generate demonstration episodes with a script, with random bag positions.
  • Record synchronised camera, joint and command data, and convert it to HDF5.
  • Train and evaluate imitation-learning policies on the recorded episodes.
  • Test mapping and navigation with the mobile base.

System architecture

  • One joint command publisher. All inputs go through the motion server. It solves the arm poses with MoveIt, checks each path against the head camera and the cell fixtures, and sends smooth joint paths at 50 Hz.
  • Robot interface names. A simulated version of the AgiBot GDK interface runs on Genie Sim. 11 of 11 GDK acceptance tests pass against the simulation. Use-case code that uses the GDK names can then run on the real robot with no change.
  • One cell file. One Python generator makes the cell scene and the list of colliders. The planner and the tests use the same list. 199 asset tests check the layout.

Cell

The cell is a U shape. The pick table is on the left, the conveyor is at the front and the sort rack is on the right. The G2 drives into the open side of the U. The clearance is 0.112 m on each side of the chassis.

The line has a case erector, open cartons on the conveyor, a drop gap with a floor bin, a right-angle transfer, a case sealer and a cobot palletiser. The light level at the robot is approximately 1470 lux.

Upstream Genie Sim sends only the robot poses to the renderer. Thus objects that physics moves stay at their start position on camera. The object pose relay adds one hook to the engine. It sends the poses of the bags, cartons and totes to the renderer at 25 Hz. Its cost is approximately 0.05 ms for each physics step.

Packing

The packing demo drives the G2 into the cell on odometry. Then it plans each arm move with MoveIt. The waist turns to the work area first, and then the arm moves. While the arms move, the base holds its position. Without this hold, a reach can push the free base by up to 23 cm.

The planner rejects a path if an arm comes nearer than 0.20 m to the head camera, or nearer than 0.015 m to a fixture.

Teleoperation and data

The keyboard teleoperation works over SSH. The operator selects an arm and moves its tool in steps of 1 to 50 mm. The node solves the joint positions with MoveIt. The operator can also turn the waist, close the grippers and start or stop a recording. A SpaceMouse gives the same functions.

The recorder writes an MCAP bag. Then it converts the bag to HDF5 with the head RGB and depth frames, the joint states, the joint commands and a group resampled to 30 Hz. The default profile writes approximately 1.1 MB/s, not 78 MB/s for the raw streams.

The episode generator makes demonstrations with a script. It sets a random bag, position and yaw in the reachable area, resets the scene, runs the pick task and records the result.

Pilot dataset

  • 20 of 20 episodes are successful. A scorer reads the bag position after each episode. All 20 bags are in the carton.
  • One episode takes 42.4 s of wall time. Physics stays at 99.7 Hz and the head camera at 30 Hz during data generation.
  • The grasp uses an attach and release at this stage, because a gripper cannot hold the rigid placeholder bag.

One pilot episode from the head camera: start, grasp, lift, transfer, place and end. At the end, the bag is in the carton.

Training

The learning package converts the HDF5 episodes to a dataset and trains an ACT-style policy or a behaviour cloning policy. The validation split uses complete episodes, so no frame of a validation episode is in the training data.

A first test trained a small model on the CPU for 300 steps, with 16 training episodes and 4 validation episodes. The validation loss decreased from 0.45 to 0.075. This test shows that the pipeline works. It is not an evaluation of a policy. Full training runs on a cloud GPU.

L1 loss on normalised actions, pilot dataset, CPU, 300 steps.

Mobility

A mobile version of the scene frees the G2 base and adds two chassis lidars. slam_toolbox makes the map, AMCL finds the robot position, and Nav2 drives the robot.

Packages

The repository contains the Docker images, the cell assets and these ROS 2 Jazzy packages. Each package has its own README and tests.
