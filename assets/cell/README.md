**Why the line turns 90° after the conveyor.** A straight line (erector 2.2 + conveyor 3.6 + gap 0.3 + sealer 1.6 +
palletiser 2.2 m = 9.9 m) does not fit the room's 9.8 m inner length with the conveyor centred on the robot. The
conveyor discharges over the drop gap onto a right-angle transfer; sealer and palletiser run along +X.

**Floor bin placement.** Bags that stay on the belt past the pack position ride off the conveyor's discharge end.
The cartons bridge the 0.30 m gap to the transfer (a carton is 0.60 m long), a loose bag (0.21–0.30 m) does not:
it drops through the gap. The red bin (0.60 × 0.80 × 0.70 m) sits directly under the gap, its +Y rim flush with
the conveyor's end (Y -1.803; the conveyor's end legs and cross members at Y -1.73..-1.77 stay outside it), and
slides 0.5 m under the open-frame transfer (frame underside 0.72 m, bin rim 0.70 m; transfer legs at X ±0.335,
outside the bin's ±0.302). Its interior spans the whole belt width (X 0.346..0.854 vs guides at 0.375..0.825) and
the whole gap. A stray bag (`/World/LineBags/Bag_InBin`) lies in it for the story.

**Collider export.** `build.py` also writes `cell_colliders.json` (oriented boxes of all 198 fixture colliders,
bags excluded) next to `cell.usda`; `g2cell_demo.env_check` uses it to keep planned arm paths off the fixtures.

### Arm-vs-fixture contact in the mobile scene (why the planner checks fixtures)

In the mobile scene the base is free and the G2's arms do collide with the cell: a right-arm path brushing the rack
upright kicked the base 6° in 0.16 s and 40° over one reach (`output/v2_work/js_t5.csv`, matched to
`env_check` penetration -0.017 m at the same instant). `g2cell_demo.packing_demo` therefore checks every joint path
(waist + arm, plus the idle tucked arm) against `cell_colliders.json` (≥ 0.015 m) and the head (≥ 0.20 m), and
holds the base with a closed-loop twist on `/odom` while the arms work (wheel drives are velocity-only, kd 10,
no brake). Closing the gripper *on* the rigid 0.21 m bag pushed the base 3.2 cm; the demo closes 20 mm above it.

## Deviations and fixes

1. **Pick table moved 0.10 m toward the robot** (centre Y 0.95 -> 0.85). See Reachability.
2. **Upstream crates stacked 2 high** (two positions), because only two 600 mm crates fit single file upstream.
3. **Tote spawn backoff 14 mm up-slope.** With the slot frame's front-bottom edge on the stop bar, PhysX pushed
   every tote 13.7 mm up-slope at start; they now spawn where they settle (drift 0.3 mm).
4. **Conveyor stop gate fix (asset bug, fixed in `conveyor/build.py`):** the gate rod started inside the static
   `Frame/GateActuator` collider, so PhysX pushed the gate (and the pack crate) up 15 mm. The pair is now filtered
   (rod slides in the cylinder); gate stays at 0.800, crate at 0.820.
5. **Stop-gate joint inactive in the Genie Sim scene.** Genie Sim's `kit/stage.py:_configure_drives()` classifies
   every revolute/prismatic joint on the stage by robot-joint name regexes and aborts on `StopGatePrismatic`.
   Upstream is not edited, so `cell.usda` deactivates `/World/Conveyor/Joints/StopGatePrismatic` and makes the gate
   kinematic at its lowered pose. Stage 3 must drive the gate kinematically (or handle the joint).
6. **Render stage shows scene rigid bodies at their authored pose.** Genie Sim publishes `/tf_render` only for robot
   links, so crates/bags never move in the camera images even if PhysX moves them. Fine for a static cell;
   Stage 3+ (moving crates, grasped bags) needs a pose relay for scene bodies.
7. Bags are rigid placeholders; deformable bags are Stage 4.

## Reachability (MoveIt `/compute_ik`, `ros2 run g2cell_demo reach_check`)

Target = fingertip point (0.125 m beyond `arm_*_end_link`), gripper pointing down, 8 yaws x 4 tilts; "waist" =
torso yaw `idx05_body_joint5` seeded at 0/30/60/90 deg (fixed during IK). Spawn zone 0.50 x 0.90 m centred
on the table, fingertips 0.10 m above its bottom (z 0.99). Output: `output/stage2/reach_check.{txt,json}`.

| Target (fingertips, cell frame) | Left arm | Right arm |
|---|---|---|
| spawn near-inner (+0.20, +0.40, 0.99) | yes (yaw 0, tilt 20) | only with waist -60 deg |
| spawn far-inner (-0.30, +0.40, 0.99) | yes (yaw 90, tilt 20) | only with waist -60 deg |
| spawn centre (-0.05, +0.85, 0.99) | yes (yaw 90, tilt 40) | no |
| spawn near-outer (+0.20, +1.30, 0.99) | **no** (any waist yaw) | no |
| spawn far-outer (-0.30, +1.30, 0.99) | **no** (any waist yaw) | no |
| above pack crate (0.60, 0, 1.144) | yes (yaw 0, tilt 0) | yes (yaw 0, tilt 0) |

With the spec table position (Y 0.95) the first run gave: inner corners (Y 0.50) left yes; centre
(-0.05, 0.95) and outer corners (Y 1.40) no for both arms. IK is randomised (KDL + seed jitter), so a single "no"
means no solution was found in 4 waists x 32 orientations x 4 seeds.

A left-arm reach map at z 0.99 (`output/reach_map.py`) shows the reachable band at table height is Y <= ~0.9 for
X -0.2..0.5 with a fixed base. The arm is too short for the far half of a 0.9 m long zone, so no small shift
makes the outer corners (Y 1.30) reachable from a stationary base. Waist yaw re-aims the shoulder but hardly moves
it. Applied: table -0.10 m in Y (the most the 0.318 m chassis half-width allows). Proposals for the outer half:
(a) restrict bag spawning to Y <= 0.85 (the placeholder bags already sit there except Bag_03), (b) let the
G2 base drive ~0.3 m along +Y for far picks (it is wheeled), or (c) turn the table 90 deg; (c) clashes with the
conveyor (X >= 0.305) and the rack front (X <= -0.455), so it needs a narrower table.
The right arm cannot reach the table from the base pose; the scripted demo therefore uses it inside the pack crate.
